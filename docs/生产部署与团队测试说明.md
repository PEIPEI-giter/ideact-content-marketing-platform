# Ideact 生产部署与团队测试说明

## 交付信息

- 公网地址：<https://121.41.88.142/>
- 前端：React + TypeScript + Vite
- 服务端：Node.js + Express + TypeScript
- 运行方式：nginx HTTPS 反向代理到 `127.0.0.1:8080`，应用由 `systemd` 的 `ideact.service` 管理
- 权限：当前是单用户后台，只有“运营管理员”一种角色

测试账号密码属于生产访问凭据，不写入 Git。项目负责人应通过团队密码管理工具或一对一安全渠道发放。

## 生产目录

```text

├─ dist/                       # 前端生产构建
├─ server/                     # 服务端代码
├─ data/                       # 业务 JSON 数据
```

当前版本备份目录采用 `/home/peipei/backups/ideact-<发布时间>/`。部署失败时，发布脚本会恢复旧目录、systemd 服务和 nginx 配置。

## 环境配置

从 `.env.example` 创建服务器 `.env`，只在服务器填写真实值。至少配置：

- `MVP_USER_EMAIL`、`MVP_USER_PASSWORD`：后台登录账号。
- `MVP_COOKIE_SECURE=true`：生产 HTTPS Cookie。
- `DASHSCOPE_API_KEY`：千问文字与图片模型。
- `ALIBABA_CLOUD_ACCESS_KEY_ID`、`ALIBABA_CLOUD_ACCESS_KEY_SECRET`：百炼与云手机服务端鉴权。
- `KB_*`：知识库名称、工作空间、索引、地域和 Endpoint。
- `ALIYUN_CLOUD_PHONE_INSTANCE_ID`、`ALIYUN_REGION_ID`：云手机实例与地域。

密钥不得写入前端代码、Git、测试报告或聊天截图。

## 数据文件

项目当前没有关系型数据库，使用服务端 JSON 持久化：

| 文件 | 内容 | 是否提交 Git |
|---|---|---|
| `data/content-workspace.json` | 创作对象、选题、简报、文案、图片和创作记录 | 否 |
| `data/publishing-jobs.json` | 发布任务、进度、结果和人工核验 | 否 |
| `data/private-inbox.json` | 关联账号、私信会话和消息 | 否 |
| `data/examples/*.json` | 脱敏空结构样例 | 是 |

服务端采用临时文件写入后原子重命名，避免写到一半留下损坏文件。备份生产环境时同时备份 `data/`、`.env` 和 `public/generated-images/`。

## 启动与检查

本地开发：

```bash
npm ci
npm run dev:api
npm run dev
```

上线前检查：

```bash
npm run typecheck
npm test -- --run
npm run build
npm audit --omit=dev
```

生产服务器检查：

```bash
sudo systemctl status ideact
sudo journalctl -u ideact -n 100 --no-pager
sudo nginx -t
curl -I https://121.41.88.142/
```

## 团队测评建议

1. 登录后先检查运营概览、知识库列表和四个一级业务模块。
2. 按“创作对象 → 生成选题 → 创作简报 → 文字定稿 → 图片制作”跑一条内容生产主流程。
3. 模型调用会产生费用，测试前确认使用范围；不要连续重复点击生成或发布。
4. 云手机发布使用非正式内容和专用测试账号，完成后在手机端人工核验。
5. 私信聚合测试不得使用真实客户隐私内容；先验证账号关联、通知过滤、会话去重和聊天页同步。
6. 记录问题时附上模块、操作步骤、发生时间、预期结果和实际结果，不附 AccessKey、Cookie 或密码。

## 已知边界

- 当前仅有一个运营管理员角色，没有多角色权限系统。
- 内容工作区是单用户服务端文件，不支持多人同时编辑冲突合并。
- 定时发布依赖服务器持续运行，平台侧最终发布结果仍需人工核验。
- 云手机、小红书页面结构和第三方模型接口变化可能导致外部能力暂时不可用。
- `public/vendor/wuying/` 的无影 Web SDK 受供应商分发约束，不进入公开代码包；部署时需单独提供。
